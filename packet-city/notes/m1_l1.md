# M1 · L1 — First Hello

**Objective tags (CompTIA Network+ N10-009)**

- **1.2** Compare and contrast networking appliances, applications, and functions (router; hosts as end devices)
- **5.2** Given a scenario, troubleshoot common cabling and physical interface issues (link lights)
- **5.5** (light touch) Given a scenario, use the appropriate tool or protocol to solve networking issues (`ping`)

> Check these numbers against the current official objectives PDF before release; CompTIA renumbers between exam versions.

**One-sentence idea.** Hosts are the devices people use, links join them, and a router connects the home network to other networks; the link light tells you whether a cable's connection is alive.

**Target length.** About 6 minutes.

**Scenes.** `m1_l1_hook` → `m1_l1_concept` → `m1_l1_realterms` → `m1_l1_walkthrough` → `m1_l1_wrong` → `m1_l1_recap`

**Components used.** `CityMap`, `Device`, `Link`, `Packet`, `Terminal`, `FaultMarker`, `TermChip`, `GuessCard`, `RecapCard`, plus the `oneHouse` topology.

## How to use this script

1. Generate one clip per beat from `notes/m1_l1_elevenlabs.txt` (the same lines, written for text-to-speech) and save them as `audio/m1_l1_<beat>.mp3`.
2. Run `python3 scripts/build-audio.py m1_l1`. It finds where each line starts, sets every cue to it, and builds `audio/m1_l1.mp3`.
3. Open the project (`npm start`). Every `[cue: name]` below is a time event of the same name in the editor timeline; drag one if it needs a nudge.

Until a lesson's project sets `variables: {narrated: true}`, each cue holds a short default pause so the preview is watchable without audio.

## Beat 2 · Concept (about 2 min 30 s) — `m1_l1_concept`

**On screen:** the network is assembled piece by piece: laptop, phone, router, house outline, internet, cable, link light, then the first packet out and back.

[cue: laptop] Let's start with Maya's laptop. Any device that sends or receives data on a network is called a **host**.

[cue: host-chip] Maya's laptop is a host.

[cue: phone] So is her phone. So is a games console, a smart TV, even a doorbell camera. If it sends or receives data, it's a host.

[cue: router] A host on its own can't reach anything outside the house. It needs a way out. That's the job of this box: the **router**. Her phone joins it over Wi-Fi, which we'll look at later in the course.

[cue: router-chip] A router connects networks together and passes traffic between them.

[cue: house] On one side is Maya's home network: everything inside the house.

[cue: internet] On the other side is everything else: the **internet**, which is really millions of other networks joined together.

[cue: cable] Now let's join the laptop to the router. A connection between two devices is called a **link**. Here, the link is a copper Ethernet cable.

[cue: link-chip] One cable, two ends, one link.

[cue: light] Watch the router's port as the plug clicks in. That small light is the **link light**. It comes on only when the devices at *both* ends agree there's a working connection on that cable.

[cue: light-chip] Green means the cable is connected and alive. Dark means it isn't.

[cue: first-packet] Now Maya's laptop can say hello. Picture each piece of data as a courier carrying an envelope. It leaves the laptop and crosses the link to the router…

[cue: out] …and the router sends it out, toward the internet.

[cue: reply] An answer comes back the same way, router to laptop. A message out, a reply back: that's a conversation.

[cue: key-idea] So three pieces: hosts, links, and a router to reach other networks. And one little light that tells you whether the cable between two of them is alive.

[cue: row-internet] The world outside is the **internet**: other networks, reached through the router.

[cue: row-packet] And the courier with the envelope is a **packet**: one small unit of data on its way somewhere.

## Beat 4 · Walkthrough (about 1 min 30 s) — `m1_l1_walkthrough`

**On screen:** the working network at the top, a terminal at the bottom. Three pings travel out and back while the terminal prints each reply.

[cue: ping-intro] Let's test Maya's connection the way a technician would, with a tool called **ping**. Ping sends a small test message to an address and waits for a reply.

[cue: type] We'll ping 1.1.1.1, the address of a well-known server on the internet. "Dash c three" means "send three and stop".

[cue: hop-1] First ping. Hop one: laptop to router, across the cable. Hop two: router out to the internet. Then the reply comes home the same way.

[cue: hops-2-3] Two more, same path, same result.

[cue: read-result] Three sent, three received, zero percent loss. That tells us every link on the path works, in both directions. The time, about fourteen milliseconds, is how long each round trip took.

## Beat 5 · What went wrong? (about 1 min 30 s) — `m1_l1_wrong`

**On screen:** the plug slides a little way out of the router port, the link light goes dark, the laptop turns red, ping fails, then a guess card with a 5-second countdown.

[cue: next-day] The next morning, Maya moves her desk over to the window. She plugs everything back in…

[cue: broken] …and the internet's gone again.

[cue: ping-fail] Ping can't even get started. "Network is unreachable": the laptop has no working link to send anything on.

[cue: guess] Your turn. The laptop is on. The router is on. But the link light on the router's port is dark. What's the most likely problem? Pause the video if you want more time.

[cue: reveal] It's B. A dark link light is a physical problem with that one cable or its ports. If Maya's internet provider were down, the cable between her laptop and router would still be fine, so the light would stay on.

[cue: zoom-fault] Here's the culprit. The plug went in, but its clip never clicked, so it slid back out of the port.

[cue: fix] Push it in until it clicks… the link light comes back… and ping works again.

[cue: rule] So here's your first troubleshooting rule: **link light dark? Check the physical connection first.** Reseat both ends of the cable, then try another cable or another port.

[cue: but] And if the light is on but there's still no internet? Then that cable is fine, and the problem is somewhere else. Finding where is what the rest of this course is about.

## Accuracy notes for the reviewer

- **Change from the outline:** the outline's fault is "cable in the wrong router port". On a real home router, plugging into the WAN/Internet port instead of a LAN port usually still gives a link light, so that fault would not leave the light dark. The script uses a cable that is not fully seated instead, which does leave the light dark. A wrong-port fault (light on, still no internet) fits better in a later lesson on addressing or DHCP.
- The `ping` output is in Linux format (`ping -c 3`). On Windows the command is `ping -n 3 1.1.1.1` and the output looks different; mention this in the lab notes.
- "Network is unreachable" is what Linux prints when it has no usable route, which is what happens once the only wired link is down and no Wi-Fi is connected. Windows shows `PING: transmit failed. General failure.` in the same situation.
- The link light rule is a simplification: a lit LED shows the physical link is up, not that data will pass. The final narration line says this directly.
